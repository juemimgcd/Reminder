# Reminder 的受控 Agentic RAG

企业知识库采用混合检索作为证据入口，由一个 Agent 按需拆题、选择允许的数据源、改写查询和补搜。
本实现沿用现有回答 API、检索范围、引用校验和耐久 Answer Run，不要求构建全局知识图谱。

## 实际执行路径

1. `MemoryAgent` 根据回答模式确定允许的数据源，执行一次初始检索。
   文档检索仍使用现有向量、关键词及可选稀疏检索；跨来源结果由现有 RRF 融合。
2. `ConfiguredModelGateway` 在生成回答的同一次模型调用里要求 `retrieval_assessment`。
   每个需求包含稳定 ID、子问题、`supported` / `missing` / `conflicting` 状态及证据 ID，最多八项。
3. 初始证据能覆盖问题且引用完整时立即结束，不额外运行规划器或评审模型。
4. 有缺口时模型通过 `decision=tool` 调用 `search_documents`、`search_memories`、
   `search_profile` 或 `search_relations`，工具集合受当前回答模式约束。
   独立子问题可以在一轮中请求多个搜索；有依赖的查询根据前一轮结果生成。
   当前工具按顺序执行，尚未增加并行调度或外部业务 API。
5. 下一轮读取补搜证据和上一轮需求表。遗漏的需求会保留，不能通过删除缺口提前结束。
   相同 ID 不允许被改写成另一个子问题。已标为支持的需求若不再有可见证据，会重新标为缺失。
6. 过早的 `final` 若缺少覆盖或引用，会在预算允许时获得修正轮次。
   最终回答仍无法覆盖问题时返回证据不足；所有模式若因预算耗尽停在工具/审查步骤，明确返回容量错误，
   不把进度说明交付为答案。规划阶段与最终交付共用引用解析规则，最终过滤后再次检查各子问题是否仍有
   有效引用；覆盖丢失时替换为证据不足。仅证据 ID 分组在本次运行中传递，不新增需求正文的持久化。

`general_chat` 保持不使用私有来源。显式选择的旧 `multi` 执行路径保留，其确定性多来源检索不被
包装成这条单 Agent 工作流。默认 `single` 路径启用上述行为，无需数据库迁移。

## 预算与终止

在 `memoria.json` 的 `memory_agent` 下配置；以下是默认值：

| 配置 | 默认值 | 含义 |
|---|---:|---|
| `reasoning.max_steps` | 3 | 最多三轮有效模型决策，最后一轮不提供工具 |
| `reasoning.total_output_tokens` | 3600 | 整个生成阶段的输出 token 预算 |
| `answer.max_output_tokens` | 1200 | 单次模型调用最大输出 token |
| `tools.max_calls` | 4 | 整个生成阶段最多四次工具请求；被拒绝或失败也占用次数 |
| `tools.timeout_seconds` | 8 | 单次工具执行期限；不配置时使用默认值 |
| `tools.observation_max_chars` | 2000 | 工具观察上下文字符预算，保留能放入预算的最近完整记录 |

请求内部的 `max_model_calls`、`max_prompt_tokens`、`max_completion_tokens` 仍然生效。
生成阶段沿用 `PhaseTimeouts.generate` 默认 90 秒总期限，包含模型调用、重试和补搜。
这些预算跨模型重试和 fallback 累计，不会切换模型后重置；已有证据和需求表也会继续保留。

有 provider usage 时按其计数扣减预算。明确返回 HTTP 错误且没有 completion 的调用只占调用次数与时限，
不把请求的最大输出量当作已输出 token；这不保证上游未计费，缺少 usage 仍标记 `usage_estimated`。
返回内容但缺少 usage，或发生结果未知的传输错误时，按消息 UTF-8 字节数和请求的最大输出保守扣减预算。
有备用模型时，结果未知的失败会提前切换；重试也不会占用最后一次可用于备用模型的调用机会。
预算跨模型累计，备用模型仍不能越过总预算。上下文预检使用字节估算，
因此小上下文模型可能提前缩减证据或触发容量错误。这不是精确 tokenizer 计数或金额计费；
现有 `cost=0` 不代表调用免费。

同一轮回答内，已完成的同工具、同查询（归一化空白）、同有效 top-k 搜索会被拒绝重复执行。
失败的搜索仍可在剩余预算内重试。上下文先按优先级选择能容纳的证据，为每项预留至多 128 字符的
最小正文摘录，再按优先级分配余量，保留完整的证据 ID。极小预算也优先保留首项，不跳过新证据去取旧证据。
初始检索为空时不再立即重复原查询，由 Agent 决定如何改写或更换允许的数据源。

## 权限、隐私和证据边界

- 模型只提供 `query` 和 `top_k`。读取工具拒绝其他参数，owner、知识库、回答模式由服务端注入。
- 工具调用不能增加 top-k 上限或扩展允许的数据源；写工具仍只形成原有审批提案。
- 需求表、查询正文和简短推理进度仅在本次生成调用内使用，不新增这些内容的日志或持久化字段。
  审计记录仅增加需求数量、未解决数量和覆盖状态，沿用已有的模型/工具调用记录。
- `supported` 是模型对相关性与充分性的判断。运行时只能核验结构、可见引用、需求保留和预算，
  不能保证模型已经列全所有子问题，也不能证明每个自然语言结论被证据蕴含。
- 当前继承 owner/知识库范围；没有在本次改造中实现企业组织 ACL、连接器身份透传或撤权同步。
  文档版本、生效时间及同步新鲜度仍由现有索引与来源元数据负责，Agent 不会自动修复过期索引。
- 未引入新的 reranker、GraphRAG 索引、外部联网搜索或工单 API。它们可作为未来独立的受控检索工具接入。

## 验证边界

仓库现有单元测试覆盖来源范围、grounding、引用、运行时失败等基础契约。
`server.eval.runner` 默认使用已有固定预测数据，不调用真实模型，不能作为新 Agent 搜索策略质量的证明。
部署前仍需用已授权的真实知识库与目标模型衡量回答质量、补搜效果、拒答率和延迟。
